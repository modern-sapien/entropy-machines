usable A developer can vendor the files, tell their agent to read one document, and have a working factory with gates that actually refuse things. Nobody but me has ever run it — that is the whole of the risk, and it does not shrink by waiting.

Landed

The harness collapsed to one root. It was going to install as a nested git clone inside your project. A nested repo shadows its parent for every git query, so "which repo am I in" stopped having one answer — and ~1,000 lines existed to survive that: two roots, drift detection, a worktree path-resolution scheme, and bin/adopt, a 1,072-line installer writing hash-fenced managed blocks into three config formats plus a session hook in .claude/settings.json.

Vendoring as plain tracked files removes the second root, and everything hanging off it went with it. Net −983 lines. A nested clone is now refused by name rather than accommodated. What replaced the installer is a paragraph the agent writes itself.

  • bin/status — live state (ready, in flight, unanswered docs) as a read that writes nothing.
  • package.json + bin/entropy-machines-init — npx entropy-machines init. 44 files, no .git, name verified free. Never published.
  • tests/ — 22 black-box cases, the first this project has had.
  • Onboarding is two human steps: get the files, then one sentence to your agent.
The installer is gone and the agent writes its own pointer paragraph. Is that the right trade, or do you want state pushed at the agent each session?

Three gates were dead and looked fine

All three had been reported as working. All three were found by re-running the claim with a control, not by reading the report.

  • The commit guard exited on a traceback instead of a verdict — it read a pretty-printed store as JSONL. Fixing only the crash turned it into a gate that silently passed everything, which is worse; caught only because the control ran too.
  • Handoff couldn't read dispatch's notes. An out-of-scope file was copied without comment four seconds after dispatch recorded the note forbidding it. A denylisted file was overwritten after dispatch printed ENFORCED denylist. Claims were never released, so issues showed in flight forever.
  • A date format I invented, shipped hours earlier. --date=format-utc: is not a git format. Both audit modes — the ones CI would run — printed fatal: and exited zero. The 21-case suite stayed green through it, because every existing test drove hook mode. That gap is case 22.

Not run: Linux or Windows; a monorepo; a repo with submodules or an existing core.hooksPath; a non-Claude agent following the doctrine; the launchd scheduler install end to end. An unmentioned gap reads as a passing check, so those are the gaps.

One that isn't filed, because it's about how this was built

Every agent today ran with disjoint file scopes rather than in isolated worktrees — the Agent tool branches the session's repo, which was a different repo. They could see each other's uncommitted work, and one git add -A of mine swept a live agent's edits into an unrelated commit. Nothing was lost. But that is the exact hazard this project exists to prevent, and it happened while building it.
